# Go Runtime Internals

Source: Go runtime source (go/src/runtime), official design docs, GopherCon talks, Dmitry Vyukov's design docs.

## GMP Scheduler Model

```
G = Goroutine (lightweight user-space thread, ~2-4KB initial stack)
M = Machine (OS thread, managed by runtime)
P = Processor (logical processor, scheduling context, GOMAXPROCS count)

Relationship: G runs on M, M must acquire P to execute G.
```

### Components

| Component | Role | Count |
|-----------|------|-------|
| **G** | Unit of work. Has stack, instruction pointer, channel wait state | Millions possible |
| **M** | OS thread. Executes Go code when bound to P. Blocks on syscalls | Created on demand, cached, max `GOMAXPROCS * 10000` |
| **P** | Holds local run queue (LRQ), mcache, timer heap. Required for G execution | Exactly `GOMAXPROCS` (default: NumCPU) |

### Scheduling Cycle

```
1. P picks G from Local Run Queue (LRQ, max 256)
2. LRQ empty → steal from another P's LRQ (work stealing, take half)
3. No stealable work → check Global Run Queue (GRQ)
4. GRQ empty → check netpoller for ready I/O
5. Nothing anywhere → M parks (goes to sleep)

Each P checks GRQ every 61 schedules (prevent starvation).
```

### Work Stealing Algorithm

```
When P's LRQ is empty:
1. Check GRQ (1/61 chance even when LRQ non-empty)
2. Try steal from random P's LRQ (take half, rounded up)
3. Check netpoller (non-blocking poll)
4. Check timer heap of other Ps
5. All fail → M parks

Steal order: randomized to avoid contention on same victim.
Fairness: stolen Gs placed at tail of stealer's LRQ.
```

### State Transitions

```
G states: _Gidle → _Grunnable → _Grunning → _Gwaiting/_Gsyscall → ...

_Grunnable: In run queue, ready to execute
_Grunning:  Executing on M+P
_Gwaiting:  Blocked (channel, mutex, I/O, timer, select)
_Gsyscall:  In blocking syscall, M detached from P
_Gdead:     Finished, in free list for reuse
```

### Syscall Handling (Handoff)

```
Goroutine enters blocking syscall:
1. M releases P (P handed off to another M)
2. M blocks in kernel with G
3. Syscall returns → M tries to re-acquire P
4. No P available → G placed in GRQ, M parks

This is why Go can handle 100K goroutines doing I/O:
P is never blocked, only M blocks (and M is cheap to park/create).
```

### Spinning Threads

```
Runtime keeps min(GOMAXPROCS, # of idle Ps) spinning Ms.
Spinning M: loops checking for work (burns CPU to reduce latency).
Purpose: new runnable G gets picked up instantly without wakeup latency.
Max spinning: GOMAXPROCS (one per P).
```

## Goroutine Stack

### Growth Mechanism (Contiguous Stacks, Go 1.4+)

```
Initial stack: 2KB (was 4KB pre-1.19, reduced for density)
Max stack: 1GB (configurable via runtime/debug.SetMaxStack)

Growth trigger: function prologue checks SP against stack guard.
If stack too small:
1. Allocate new stack (2x current size)
2. Copy entire old stack to new stack
3. Adjust all pointers that reference old stack (stack scanning)
4. Free old stack

Shrink: GC halves stack if <25% used (during stack scan).
```

### Stack Split Hot Spot

```
Problem: function at exact boundary causes grow/shrink repeatedly.
Old: segmented stacks had "hot split" problem (Go 1.0-1.3).
Current: contiguous copy avoids hot split but copy cost on growth.

Mitigation:
- Runtime grows 2x (amortized O(1))
- nosplit functions (//go:nosplit) skip check for tiny leaf funcs
- Compiler inlines small funcs, reducing call depth
```

### Implications for Performance

```
- 2KB stack = 500K goroutines per GB RAM (just stacks)
- Stack growth has O(n) copy cost (n = stack size at that moment)
- Deeply recursive functions pay more (consider iterative)
- Stack-allocated vars: zero cost. Heap-allocated: GC pressure.
- Pointer to stack var prevents shrink until pointer is gone
```

## Preemptive Scheduling

### Non-Cooperative Preemption (Go 1.14+)

```
Before 1.14: preemption only at function calls (cooperative).
Problem: tight loop without calls starves other Gs on same P.

After 1.14: asynchronous preemption via OS signals.
Mechanism (Unix):
1. sysmon detects G running >10ms without preemption point
2. Sends SIGURG to M running that G
3. Signal handler sets preemption flag
4. G suspended at next safe point (recorded in stack map)
5. G placed back in run queue, P picks next G

Safe points: generated by compiler, locations where all live pointers
are known (needed for GC correctness).
```

### sysmon (System Monitor)

```
Dedicated M, no P required. Runs in background loop:
- Polls netpoller if no other M did recently (10ms)
- Retakes P from syscalling M (>20μs for handoff, >10ms for preemption)
- Fires timers if no P did
- Triggers GC if needed
- Detects deadlock (all Gs waiting, no timer)

Sleep pattern: starts at 20μs, backs off to 10ms max when idle.
```

## Netpoller (I/O Multiplexing)

```
Platform-specific epoll/kqueue/IOCP integration in runtime.

Goroutine does network I/O:
1. Runtime registers fd with netpoller (epoll_ctl)
2. G parked (_Gwaiting), removed from P's run queue
3. fd becomes ready → netpoller marks G as runnable
4. G placed in P's run queue or GRQ
5. G resumes from where it left off

Result: blocking API semantics, non-blocking implementation.
Each goroutine thinks it has its own connection.
Runtime multiplexes thousands on handful of OS threads.
```

### Integrated Poller Check Points

```
- Schedule loop (every iteration)
- Syscall return (if P was idle)
- sysmon timer (every 10ms when idle)
- GC STW entry (drain pending I/O first)
- findrunnable (when looking for work)
```

## Timer Implementation (Go 1.14+ per-P timers)

```
Before 1.14: single global timer heap (timerproc goroutine, contention).
After 1.14: per-P timer heap (4-heap, min-heap).

time.After/Timer/Ticker → timer added to current P's heap.
Timer fires → associated G made runnable on that P.

Implication:
- time.After in loop = timer per iteration (all fire eventually, no leak in 1.23+)
- time.NewTimer + Reset = reuse single timer (still best practice)
- Timer resolution: ~1ms minimum (runtime checks timers in schedule loop)
```

## Channel Internals

```
type hchan struct {
    qcount   uint   // elements in buffer
    dataqsiz uint   // buffer capacity
    buf      unsafe.Pointer // circular buffer
    sendx    uint   // send index
    recvx    uint   // receive index
    recvq    waitq  // waiting receivers (sudog linked list)
    sendq    waitq  // waiting senders
    lock     mutex  // protects all fields
}

Unbuffered (cap=0): direct copy sender→receiver (no buffer, rendezvous).
Buffered (cap>0): ring buffer with lock.

Optimization: if receiver already waiting, sender copies directly to
receiver's stack (no lock for the data copy itself, called "direct send").
```

## Key Runtime Tunables

| Variable | Default | Purpose |
|----------|---------|---------|
| `GOMAXPROCS` | NumCPU | Number of Ps (parallel execution limit) |
| `GOGC` | 100 | GC frequency (% of live heap growth before next GC) |
| `GOMEMLIMIT` | math.MaxInt64 | Soft memory limit for heap |
| `GODEBUG=schedtrace=N` | off | Print scheduler state every N ms |
| `GODEBUG=scheddetail=1` | off | Detailed per-P/M/G state in schedtrace |
| `GODEBUG=gctrace=1` | off | Print GC stats per cycle |
| `GODEBUG=asyncpreemptoff=1` | off | Disable async preemption (debug only) |
| `runtime.LockOSThread()` | - | Pin G to M (CGO, GUI, TLS) |
| `runtime/debug.SetMaxStack` | 1GB | Max goroutine stack size |
| `runtime/debug.SetMaxThreads` | 10000 | Max OS threads |

## Performance Implications Summary

| Understanding | Optimization |
|---------------|-------------|
| GMP model | Right GOMAXPROCS, understand scheduling latency |
| Work stealing | Keep work balanced across Ps; unbalanced = idle Ps |
| Stack growth | Avoid deeply recursive hot paths; stack copy cost |
| Preemption | Tight loops are fine since 1.14 (no starvation) |
| Netpoller | Goroutine-per-connection is correct pattern |
| Channel lock | Unbuffered channels = lighter than buffered for signaling |
| sysmon | Short syscalls (<20μs) don't trigger handoff |
| Timer per-P | Don't create millions of timers; reuse where possible |

## Common Misconceptions

| Myth | Reality |
|------|---------|
| "Goroutines are green threads" | Partially. Go has M:N scheduling but with unique features (stack growth, preemption, integrated netpoller) |
| "GOMAXPROCS limits goroutines" | No. It limits parallelism (concurrent execution on CPUs). You can have millions of goroutines with GOMAXPROCS=1 |
| "Channels are slow" | Unbuffered direct-send is ~50ns. Comparable to mutex for simple signaling |
| "More GOMAXPROCS = faster" | Only for CPU-bound. I/O-bound apps often faster with fewer (less contention) |
| "Goroutine = always cheap" | 2KB stack + scheduling overhead. 10M goroutines = 20GB just in stacks |
| "runtime.Gosched() needed for fairness" | Since 1.14, async preemption handles this. Gosched rarely needed |

## runtime/debug Production Utilities

```go
import "runtime/debug"

// Set GOMEMLIMIT programmatically (overrides env var)
debug.SetMemoryLimit(3750 * 1024 * 1024) // 3750 MiB

// Set GOGC programmatically
debug.SetGCPercent(200) // or -1 to disable

// Read build info (module versions, VCS revision)
info, ok := debug.ReadBuildInfo()
// info.Main.Version, info.GoVersion, info.Settings (vcs.revision, etc.)

// Force GC + free memory to OS
debug.FreeOSMemory() // aggressive: forces GC + returns all free memory

// Set max OS threads (prevent thread explosion from blocking cgo)
debug.SetMaxThreads(20000)

// Set max stack size per goroutine
debug.SetMaxStack(512 * 1024 * 1024) // 512MB (default 1GB)

// Stack trace on panic
debug.SetTraceback("all") // or env GOTRACEBACK=all

// Crash on unexpected GC pause (detect stop-the-world regressions)
debug.SetPanicOnFault(true) // debug only
```

## runtime Package Key Functions

```go
import "runtime"

// Goroutine management
runtime.NumGoroutine()          // current count
runtime.Goexit()                // terminate goroutine (runs defers)
runtime.Gosched()               // yield processor (rarely needed since 1.14)
runtime.LockOSThread()          // pin goroutine to OS thread (CGO, GUI, TLS)
runtime.UnlockOSThread()

// Memory stats (prefer runtime/metrics for new code)
var stats runtime.MemStats
runtime.ReadMemStats(&stats)
// stats.HeapAlloc    - bytes in use
// stats.HeapSys      - bytes obtained from OS
// stats.NumGC        - completed GC cycles
// stats.PauseTotalNs - total STW pause time
// stats.GCCPUFraction - fraction of CPU used by GC

// Force GC (rarely needed, let pacer handle it)
runtime.GC()

// CPU/OS info
runtime.NumCPU()       // logical CPUs
runtime.GOMAXPROCS(0)  // current GOMAXPROCS (0 = query without changing)
runtime.GOOS           // "linux", "darwin", "windows"
runtime.GOARCH         // "amd64", "arm64"

// Stack management
buf := make([]byte, 1024*1024)
n := runtime.Stack(buf, true) // true = all goroutines
fmt.Printf("%s\n", buf[:n])

// Finalizers (use sparingly)
runtime.SetFinalizer(obj, func(o *T) { o.Close() })
runtime.KeepAlive(obj) // prevent GC until this point
```
