# Question Bank

The goal of grilling is alignment, not interrogation. Ask one question at a time, keep each short, and close the branch on the answer. A question bank is a fallback, not a checklist to dump.

## Goal: what done looks like

- "What does done look like, in one sentence?"
- "Who uses this, and what do they need it to do?"
- "What would a good outcome change?"

## Boundaries: what stays out

- "What is explicitly out of scope?"
- "What should we NOT change, even if it seems related?"
- "Is there a constraint (time, budget, compatibility) I should respect?"

## Seams: where behavior is observed

- "Where will we observe the behavior working?"
- "What is the public interface or entry point?"
- "For tests: which seam should we agree to test at?"

## Tradeoffs: when multiple paths exist

- "There are two ways to do this: X and Y. Which fits this context, and why?"
- "What happens if we do the simplest version first?"
- "What would make you reject this approach?"

## Signals: how we know it worked

- "How will we know it worked?"
- "What is the acceptance test you will run?"
- "What would count as a failure?"

## Listening rules

- Read docs, tickets, and code the user references BEFORE asking; never ask what they already answer.
- When the answer is clear, close the branch. Do not re-ask or hedge.
- One question per turn. Silence between questions lets the user think.
- Restate closed branches back once before starting work.
