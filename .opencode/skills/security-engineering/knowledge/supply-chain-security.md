# Supply Chain Security

## SLSA Framework (Supply-chain Levels for Software Artifacts)

### Level 1: Documentation
- Build process exists and produces provenance
- Provenance describes how artifact was built
- Minimum: automated build with generated metadata

### Level 2: Hosted Build
- Build runs on a hosted service (not developer laptop)
- Provenance is generated by the build service, not the developer
- Authenticated provenance (signed by build platform)

### Level 3: Hardened Builds
- Build service provides strong isolation between builds
- Provenance is non-falsifiable (tamper-resistant)
- Hermetic builds: all inputs declared, no network access during build
- Ephemeral build environments

### Level 4: Two-Party Review
- All changes require two-party review before merge
- Hermetic, reproducible builds
- Full provenance chain from source to artifact

## SBOM Generation

### SPDX Format

```bash
# Using syft for container SBOM
syft packages myapp:latest -o spdx-json > sbom.spdx.json

# Using cdxgen for source code
npx @cyclonedx/cdxgen -o sbom.json

# Validate SBOM
ntia-conformance-checker --file sbom.spdx.json
```

### CycloneDX Format

```bash
# Node.js
npx @cyclonedx/cyclonedx-npm --output-file bom.json

# Python
cyclonedx-py poetry --output bom.json

# Go
cyclonedx-gomod mod -json -output bom.json
```

### CI Integration

```yaml
# GitHub Actions SBOM generation
- name: Generate SBOM
  uses: anchore/sbom-action@v0
  with:
    artifact-name: sbom.spdx.json
    format: spdx-json

- name: Scan SBOM for vulnerabilities
  uses: anchore/scan-action@v4
  with:
    sbom: sbom.spdx.json
    fail-build: true
    severity-cutoff: high
```

## Attack Vectors

### Dependency Confusion

Attacker publishes a public package with same name as internal package but higher version.

```bash
# Prevention: scope all internal packages
npm config set @mycompany:registry https://internal.registry.com

# .npmrc
@mycompany:registry=https://internal.registry.com
//internal.registry.com/:_authToken=${NPM_TOKEN}
```

```json
// package.json -- use scoped names
{
  "dependencies": {
    "@mycompany/auth-lib": "2.1.0",
    "@mycompany/utils": "1.4.3"
  }
}
```

### Typosquatting

Attacker publishes packages with names similar to popular ones (e.g., `expresss`, `lodahs`).

Detection:
- Use lockfiles and review new dependencies in PRs
- Socket.dev or Snyk for behavioral analysis
- CI check that flags new dependencies for manual review

```yaml
# GitHub Action to detect new dependencies
- name: Detect new dependencies
  uses: hiwelo/new-dependencies-action@v1
  with:
    token: ${{ secrets.GITHUB_TOKEN }}
```

### Compromised Maintainer

- Enable npm 2FA for publishing
- Use `npm audit signatures` to verify registry signatures
- Pin to exact versions with integrity hashes in lockfiles
- Monitor for ownership transfers

## Artifact Signing with Sigstore/Cosign

### Sign Container Images

```bash
# Keyless signing (uses OIDC identity)
cosign sign --yes ghcr.io/myorg/myapp@sha256:abc123...

# Verify signature
cosign verify \
  --certificate-identity=ci@myorg.com \
  --certificate-oidc-issuer=https://token.actions.githubusercontent.com \
  ghcr.io/myorg/myapp@sha256:abc123...
```

### Sign Blobs/Artifacts

```bash
# Sign a release binary
cosign sign-blob --yes --output-signature=app.sig app.tar.gz

# Verify
cosign verify-blob \
  --signature=app.sig \
  --certificate-identity=release@myorg.com \
  --certificate-oidc-issuer=https://accounts.google.com \
  app.tar.gz
```

### CI/CD Integration (GitHub Actions)

```yaml
jobs:
  build-and-sign:
    permissions:
      contents: read
      id-token: write  # Required for keyless signing
      packages: write

    steps:
      - name: Build and push image
        id: build
        uses: docker/build-push-action@v5
        with:
          push: true
          tags: ghcr.io/myorg/myapp:${{ github.sha }}

      - name: Sign image
        uses: sigstore/cosign-installer@v3
      - run: cosign sign --yes ghcr.io/myorg/myapp@${{ steps.build.outputs.digest }}

      - name: Generate and sign SBOM
        run: |
          syft ghcr.io/myorg/myapp@${{ steps.build.outputs.digest }} -o spdx-json > sbom.json
          cosign attest --yes --predicate sbom.json \
            --type spdxjson \
            ghcr.io/myorg/myapp@${{ steps.build.outputs.digest }}
```

## Verification Policy (Kubernetes)

```yaml
# Kyverno policy to enforce signed images
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: verify-image-signatures
spec:
  validationFailureAction: Enforce
  rules:
    - name: verify-cosign-signature
      match:
        any:
          - resources:
              kinds: ["Pod"]
      verifyImages:
        - imageReferences: ["ghcr.io/myorg/*"]
          attestors:
            - entries:
                - keyless:
                    subject: "ci@myorg.com"
                    issuer: "https://token.actions.githubusercontent.com"
```

## Lockfile Hygiene

- Always commit lockfiles (package-lock.json, go.sum, Cargo.lock)
- Review lockfile diffs in PRs for unexpected changes
- Use `--frozen-lockfile` / `--ci` in CI builds
- Regenerate lockfile periodically to pick up sub-dependency patches

```bash
# CI install commands
npm ci                    # Node.js
pip install --require-hashes -r requirements.txt  # Python
go mod verify             # Go
```
