# Story Mapping

## Core Concepts

- Story maps arrange user activities horizontally (narrative flow) and details vertically (depth)
- The backbone (top row) shows the user's journey from left to right
- Vertical slices beneath each activity represent increasing sophistication or edge cases
- A horizontal line across the map defines a release: everything above the line ships together
- Maps reveal gaps that flat backlogs hide — missing steps become visible in the flow

## Key Practices

- Map the backbone first: major user activities in the order they naturally occur
- Add details below each activity: variations, edge cases, supporting steps
- Draw release lines to define MVPs and increments — each slice delivers end-to-end value
- Walk through the map as a user story: does the narrative make sense left to right?
- Update the map as understanding evolves — it's a living planning artifact

## Common Mistakes

- Building the map alone instead of collaboratively with the whole team
- Mapping technical tasks instead of user-visible activities
- Creating the map once and never updating it as scope changes

## When to Apply

- Planning a new product or major feature — need to define MVP scope
- Backlog feels like a disconnected list with no coherent user journey
- Stakeholders struggle to understand what "release 1" actually delivers
- Team needs shared understanding of how features connect into user workflows
