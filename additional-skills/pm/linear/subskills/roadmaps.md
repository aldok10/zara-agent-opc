# Roadmaps

## Purpose

Communicate direction and progress. Directional, not date-specific. Build trust through transparency.

## Principles

1. Roadmaps are communication tools, not commitments.
2. Near-term = high confidence. Far-term = directional.
3. Update regularly. Stale roadmap = no roadmap.
4. Show progress, not just plans.
5. Audience-aware: eng sees details, stakeholders see outcomes.

## Confidence Levels

| Timeframe | Confidence | Communication |
|-----------|-----------|---------------|
| This cycle | High (90%+) | Committed, specific deliverables |
| Next cycle | Medium (60-80%) | Planned, likely scope |
| 2-3 cycles | Low (30-50%) | Directional, subject to change |
| Beyond | Aspirational | Vision, no dates |

## Roadmap View Configuration

Linear Projects view:
- Group by: Team or Initiative
- Sort by: Target date
- Filter: Active + Planned (hide completed >30 days)
- Show: Progress bar, lead, target date, status

## Project Target Dates

- Set target quarter, not exact date (unless committed).
- Update target if confidence drops below 50%.
- Flag "At Risk" 2 weeks before target if <70% complete.

## Stakeholder Sharing

- Monthly roadmap review with stakeholders.
- Format: what shipped, what's next, what changed, what's at risk.
- Use Linear project updates (not separate docs).
- Link to project directly - single source of truth.

## Progress Indicators

- % complete = issues done / total issues in project.
- Supplement with milestone completion (qualitative progress).
- Velocity trend: accelerating, steady, or slowing.

## Anti-Patterns

- Exact dates on low-confidence items
- Roadmap not updated >2 weeks
- Separate roadmap doc that drifts from Linear
- No confidence levels (everything looks "committed")
- Hiding scope changes from stakeholders

## Verification

- [ ] All active projects have confidence level
- [ ] Target dates reflect current confidence
- [ ] Monthly stakeholder update delivered
- [ ] At-risk projects flagged 2+ weeks early
