# RACI Guide

## Definitions

| Letter | Role | Meaning |
|--------|------|---------|
| R | Responsible | Does the work |
| A | Accountable | Final decision authority, owns outcome |
| C | Consulted | Input before decision (two-way) |
| I | Informed | Told after decision (one-way) |

## Rules

- Exactly ONE "A" per decision/task (no shared accountability)
- At least one "R" per task
- Minimize "C" - too many slows decisions
- "A" can also be "R" (common for PMs on smaller teams)
- No role left blank - explicitly mark who is NOT involved

## Common PM Configurations

| Activity | PM | Eng Lead | Exec | Design |
|----------|-----|----------|------|--------|
| Roadmap prioritization | A/R | C | I | C |
| Technical architecture | C | A/R | I | I |
| Sprint planning | A | R | I | C |
| Customer communication | A/R | I | C | I |
| Hiring decisions | C | R | A | C |
| Release go/no-go | A | R | I | I |
| UX decisions | C | I | I | A/R |
| Budget allocation | R | C | A | I |

## When to Create RACI

- New initiative kickoff
- Cross-team projects
- After role confusion surfaces
- Org changes affecting ownership

## Anti-patterns

- Multiple A's (nobody owns it)
- Everyone is C (decision paralysis)
- RACI exists but nobody references it
- Too granular (task-level vs decision-level)

## Verification

- One A per row
- All key stakeholders appear
- Reviewed with all named parties
- Referenced in decision-making moments
