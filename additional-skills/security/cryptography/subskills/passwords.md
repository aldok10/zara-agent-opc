# Password Hashing

Argon2id, bcrypt, scrypt, pepper strategies, and migration between hashing algorithms.

## When to Load

- Implementing user password storage
- Migrating from weak hashing (MD5, SHA-256) to modern algorithms
- Tuning hash parameters for your hardware
- Adding pepper to defense-in-depth password strategy

## Key Concepts

**Algorithm Ranking (2024+)**
1. Argon2id: winner of Password Hashing Competition -- best overall choice
2. bcrypt: battle-tested, widely supported, adequate for most applications
3. scrypt: memory-hard, good but less tunable than Argon2
4. PBKDF2: acceptable only with high iterations (600k+ for SHA-256)
5. MD5/SHA-*: NEVER use for passwords (fast = crackable)

**Argon2id Parameters**
- Memory (m): minimum 64MB for interactive, 256MB+ for sensitive
- Iterations (t): minimum 3 for high memory, more for lower memory
- Parallelism (p): number of threads (usually match CPU cores for hashing)
- Salt: 16 bytes random per password (auto-generated by libraries)
- Output: 32 bytes recommended

**bcrypt Considerations**
- Cost factor: 12 minimum (2024), increase as hardware improves
- 72-byte input limit -- pre-hash with SHA-256 if passwords can be longer
- Null byte issue: some implementations truncate at first null byte
- Version: $2b$ is the current correct prefix

**Defense in Depth: Pepper**
- Secret key added to password before hashing (or HMAC after hashing)
- Stored separately from database (HSM, environment variable, KMS)
- If DB is compromised but pepper is not, hashes are much harder to crack
- Rotation requires re-hashing all passwords (or versioned peppers)

## Patterns

```python
# Argon2id with passlib (recommended)
from argon2 import PasswordHasher

ph = PasswordHasher(
    time_cost=3,
    memory_cost=65536,  # 64 MB
    parallelism=4,
    hash_len=32,
    salt_len=16,
)

hash_str = ph.hash("user_password")
# $argon2id$v=19$m=65536,t=3,p=4$...

try:
    ph.verify(hash_str, "user_password")
    if ph.check_needs_rehash(hash_str):
        new_hash = ph.hash("user_password")
        # update stored hash
except Exception:
    # invalid password
    pass
```

```python
# Migration pattern: transparent rehashing
def verify_and_migrate(stored_hash: str, password: str) -> tuple[bool, str | None]:
    if stored_hash.startswith("$argon2id$"):
        valid = argon2_verify(stored_hash, password)
        return valid, None

    if stored_hash.startswith("$2b$"):
        valid = bcrypt_verify(stored_hash, password)
        if valid:
            new_hash = argon2_hash(password)
            return True, new_hash  # caller updates DB
        return False, None

    if len(stored_hash) == 64:  # likely SHA-256
        valid = sha256(password) == stored_hash
        if valid:
            new_hash = argon2_hash(password)
            return True, new_hash
        return False, None

    return False, None
```

**Parameter Tuning Process**
1. Target: hash should take 200-500ms on your production hardware
2. Start with recommended minimums
3. Increase memory first (most effective against GPU attacks)
4. Then increase iterations until target time reached
5. Benchmark on actual production hardware, not dev machines
6. Re-evaluate annually as hardware improves

## Gotchas

- Never store plaintext alongside hashes "for recovery" -- defeats the purpose
- bcrypt silently truncates at 72 bytes -- users with long passwords get weaker security
- Argon2 memory parameter means actual RAM usage during hashing -- plan capacity
- Hash timing: use constant-time comparison to prevent timing attacks
- Password reset tokens are not passwords -- use CSPRNG + HMAC, not password hashing
- Rate limiting login attempts is complementary to strong hashing, not a replacement

## Verification

- Hash output changes between calls for same password (salt is random)
- Verification succeeds for correct password, fails for incorrect
- Hash time is within target range (200-500ms) on production hardware
- Migration function correctly upgrades old hashes on successful login
- Pepper rotation: old peppered hashes still verify with version lookup
