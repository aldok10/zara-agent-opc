# SLSA Provenance

SLSA (Supply-chain Levels for Software Artifacts) is a framework for ensuring the integrity of build artifacts. It defines levels of assurance that an artifact was built from the expected source by the expected process without tampering.

## Key Concepts

### SLSA Levels (v1.0)

| Level | Requirements | Guarantees |
|-------|-------------|-----------|
| Build L0 | No provenance | None |
| Build L1 | Provenance exists, generated by build platform | Know what was built and where |
| Build L2 | Signed provenance, hosted build service | Tamper-evident provenance |
| Build L3 | Hardened build platform, isolated builds | Tamper-resistant provenance |

Most teams should target Level 2 (achievable with GitHub Actions built-in attestation). Level 3 requires isolated/hermetic builds.

### Provenance Attestation

A cryptographically signed statement about HOW an artifact was built:

```json
{
  "_type": "https://in-toto.io/Statement/v1",
  "subject": [
    {
      "name": "registry.io/app",
      "digest": {"sha256": "abc123..."}
    }
  ],
  "predicateType": "https://slsa.dev/provenance/v1",
  "predicate": {
    "buildDefinition": {
      "buildType": "https://actions.github.io/buildtypes/workflow/v1",
      "externalParameters": {
        "workflow": {
          "ref": "refs/tags/v1.0.0",
          "repository": "https://github.com/org/repo"
        }
      }
    },
    "runDetails": {
      "builder": {"id": "https://github.com/actions/runner"},
      "metadata": {"invocationId": "https://github.com/org/repo/actions/runs/123"}
    }
  }
}
```

### Verification

```bash
# Verify GitHub attestation
gh attestation verify oci://registry.io/app:v1.0.0 \
  --owner org \
  --predicate-type https://slsa.dev/provenance/v1

# Verify with cosign
cosign verify-attestation \
  --type slsaprovenance \
  --certificate-identity "https://github.com/org/repo/.github/workflows/release.yml@refs/tags/v1.0.0" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  registry.io/app@sha256:abc123...

# Verify with slsa-verifier
slsa-verifier verify-image registry.io/app@sha256:abc123... \
  --source-uri github.com/org/repo \
  --source-tag v1.0.0
```

## Configuration Examples

### GitHub Actions Attestation (SLSA L2)

```yaml
permissions:
  id-token: write
  contents: read
  attestations: write
  packages: write

jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      digest: ${{ steps.push.outputs.digest }}
    steps:
      - uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683
      - id: push
        run: |
          docker buildx build --push -t registry.io/app:${{ github.sha }} .
          echo "digest=$(docker inspect --format='{{index .RepoDigests 0}}' registry.io/app:${{ github.sha }} | cut -d@ -f2)" >> "$GITHUB_OUTPUT"

      - uses: actions/attest-build-provenance@1c608d11d69870c2092266b3f9a6f3abbf17002c
        with:
          subject-name: registry.io/app
          subject-digest: ${{ steps.push.outputs.digest }}
          push-to-registry: true
```

### SBOM Attestation

```yaml
      - uses: anchore/sbom-action@v0
        id: sbom
        with:
          image: registry.io/app@${{ steps.push.outputs.digest }}
          output-file: sbom.spdx.json

      - uses: actions/attest-sbom@v1
        with:
          subject-name: registry.io/app
          subject-digest: ${{ steps.push.outputs.digest }}
          sbom-path: sbom.spdx.json
          push-to-registry: true
```

## Common Patterns

### Admission Control with Provenance

Kubernetes policy (Kyverno) requiring SLSA provenance:

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-slsa-provenance
spec:
  validationFailureAction: Enforce
  rules:
    - name: check-provenance
      match:
        any:
          - resources:
              kinds: [Pod]
      verifyImages:
        - imageReferences: ["registry.io/*"]
          attestations:
            - type: https://slsa.dev/provenance/v1
              predicateType: https://slsa.dev/provenance/v1
              attestors:
                - entries:
                    - keyless:
                        issuer: https://token.actions.githubusercontent.com
                        subject: "https://github.com/org/*"
```

### Sigstore Transparency Log

All keyless signatures are recorded in Rekor (transparency log):

```bash
# Search for entries related to an image
rekor-cli search --sha sha256:abc123...

# Get detailed entry
rekor-cli get --uuid <entry-uuid> --format json
```

Transparency log entries are immutable and publicly auditable -- provides non-repudiation.

### Binary Provenance (non-container)

```yaml
- uses: slsa-framework/slsa-github-generator/.github/workflows/builder_go_slsa3.yml@v2.0.0
  with:
    go-version-file: go.mod
```

SLSA L3 generators exist for Go, generic artifacts, and container images.

## Gotchas

1. `actions/attest-build-provenance` attests to the BUILD, not the source -- a compromised workflow can produce attested malicious artifacts
2. Provenance verification requires knowing the expected builder identity -- hard-code it in admission policies
3. Tag-based references in provenance (refs/tags/v1.0.0) can be moved -- verify against commit SHA when possible
4. SLSA L3 requires hermetic builds (no network access during build) -- most npm/pip builds can't achieve this
5. Rekor log entries are permanent -- accidentally signed test artifacts are visible forever
6. GitHub attestation and cosign attestation use different storage formats -- choose one standard per org

## Quick Reference

| Level | How to Achieve | Tooling |
|-------|---------------|---------|
| L1 | Generate provenance in CI | `actions/attest-build-provenance` |
| L2 | Sign provenance, use hosted CI | GitHub Actions + Sigstore |
| L3 | Isolated/hermetic builder | `slsa-github-generator` workflows |

| Tool | Purpose |
|------|---------|
| `gh attestation verify` | Verify GitHub-native attestations |
| `cosign verify-attestation` | Verify cosign-stored attestations |
| `slsa-verifier` | Verify SLSA provenance from slsa-github-generator |
| `rekor-cli` | Query Sigstore transparency log |
| `actions/attest-build-provenance` | Generate SLSA L1/L2 provenance |
| `actions/attest-sbom` | Attach SBOM attestation to artifact |
