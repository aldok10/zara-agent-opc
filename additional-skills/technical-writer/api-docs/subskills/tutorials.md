# API Tutorials

## Core Concepts
- Tutorials guide readers through a complete task from start to finish (learning-oriented)
- Structure: goal statement, prerequisites, step-by-step instructions, verification, next steps
- Progressive disclosure: start simple, add complexity only after basics are working
- Tutorials differ from reference docs: they teach by doing, not by listing all options
- Each tutorial should produce a working, verifiable result the reader can build upon

## Key Practices
- State the end result upfront so readers know what they're building toward
- List exact prerequisites: accounts, tools, versions, permissions needed before starting
- Number steps explicitly; each step produces a visible, verifiable outcome
- Include complete code at each checkpoint - don't rely on readers assembling fragments correctly
- Test tutorials end-to-end on a fresh environment before publishing

## Common Mistakes
- Assuming knowledge not listed in prerequisites (implicit "you should already know X")
- Skipping steps that seem obvious to the author but block newcomers
- Tutorials that don't work due to version drift in dependencies or APIs

## When to Apply
- Onboarding new API consumers who need guided first-use experience
- Introducing new features that combine multiple API calls in a workflow
- Creating quickstart guides for developer documentation portals
