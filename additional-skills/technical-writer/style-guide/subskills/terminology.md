# Terminology Management

## Core Concepts
- Terminology defines the canonical names for concepts, features, and components in your product
- A glossary is the single source of truth; all docs reference it, not local definitions
- Consistency: one concept = one term everywhere (UI, docs, API, support, marketing)
- Disambiguation: when a term has multiple meanings in different contexts, define each usage
- Controlled vocabulary prevents confusion when teams use different words for the same thing

## Key Practices
- Maintain a central glossary with: term, definition, context, synonyms to avoid, related terms
- Define terms at first use in any document; link to glossary for full definition
- Audit docs periodically for terminology drift (same thing called different names)
- Include API resource names and UI labels in the glossary for cross-reference
- Get terminology agreement from product, engineering, and support before codifying

## Common Mistakes
- Using internal codenames or legacy terms in customer-facing documentation
- Defining the same concept differently in different parts of the documentation
- Glossary that exists but nobody references or maintains (becomes stale immediately)

## When to Apply
- Launching new features that introduce new concepts to users
- Onboarding new writers who need to learn the product vocabulary
- Resolving confusion caused by inconsistent naming across teams or docs
