# Voice & Tone

## Core Concepts
- Voice is the consistent personality of your documentation (who you are)
- Tone adapts to context while maintaining voice (how you sound in different situations)
- Voice attributes: e.g., knowledgeable, friendly, direct, respectful
- Tone shifts: error messages (empathetic, helpful), tutorials (encouraging), reference (neutral, precise)
- Consistency in voice builds trust; readers know what to expect

## Key Practices
- Define 3-5 voice attributes with "this, not that" examples for each
- Create tone guidelines per content type: getting started (warm), reference (precise), troubleshooting (empathetic)
- Use second person ("you") for instructions; avoid first person plural ("we") unless representing the company
- Match formality to audience: developer docs can be casual; compliance docs stay formal
- Read content aloud - if it sounds awkward spoken, it reads awkward too

## Common Mistakes
- Inconsistent tone: cheerful marketing copy next to dry technical reference creates whiplash
- Overly casual tone in error messages (humor when users are frustrated backfires)
- "We" ambiguity: "we recommend" (the company? the docs team? the reader and author together?)

## When to Apply
- Establishing documentation standards for a new product or team
- Reviewing existing docs for consistency across multiple contributors
- Training new writers to match established documentation personality
