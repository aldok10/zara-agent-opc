# Harness Design

The model is frozen. Everything here is the environment around it.

Two standards are applied together:

- Five subsystems (harness engineering): instructions, state, verification,
  scope, lifecycle.
- Eight editable components (Harness2): system prompt, guardrails, memory, tool
  guidance, subagents, skills, scripts, plugins.

## Five Subsystems

| Subsystem | Job | Files |
|---|---|---|
| Instructions | startup path, rules, definition of done | `AGENTS.md`, `docs/`, `.opencode/instructions/` |
| State | what is done, what is next, why | `PROGRESS.md`, `DECISIONS.md`, `feature_list.json`, `...harness/traces/` |
| Verification | only passing commands count | `Makefile`, `scripts/`, `...harness/arch-rules.json` |
| Scope | one feature at a time, explicit done | `feature_list.json`, `templates/sprint-contract.md` |
| Lifecycle | initialize, verify, clean exit | `uv run --project scripts zara-cli init`, `zara-cli clean-check`, `templates/session-handoff.md` |

## Eight Editable Components

| Component | Where it lives | Change it when |
|---|---|---|
| System prompt | `.opencode/instructions/system.md`, `system-extended.md`, `.opencode/agent/*.md` | behavior rules or role framing drift |
| Guardrails | `opencode.json` permissions, `...harness/arch-rules.json`, `AGENTS.md` constraints | a failure must become impossible |
| Memory | `mcp/zarust-memory` (zmem-mcp), `~/.zara/memory.db`, `PROGRESS.md`, `DECISIONS.md`, `...harness/ledger.jsonl` | recall is wrong or evidence is lost |
| Tool guidance | `AGENTS.md` MCP reference, `.opencode/skills/` | a tool is used incorrectly |
| Subagents | `.opencode/agent/*.md` | delegation or budgets are wrong |
| Skills | `.opencode/skills/`, `additional-skills/` | a procedure repeats |
| Scripts | `scripts/`, `Makefile`, `uv run --project scripts zara-cli init` | a check is manual or flaky |
| Plugins | none by design | never; V2 rejects the v1 API |

## Task-Level Recursion

`...harness/run_improvement.py` implements Propose, Probe, Compose:

1. Propose: a candidate overlay in `...harness/candidates/` edits the harness
   (today: an addition to the primary agent prompt).
2. Probe: the candidate runs the same task as the baseline, through the real
   OpenCode CLI, and the task checks score both runs.
3. Compose: a candidate is adopted only when it passes checks that the baseline
   fails. Everything else is rejected with the contrast recorded.

Dry-run first. Each probe is a real model call.

## Harnessing-Level Recursion

Evidence persists in three places:

- `...harness/ledger.jsonl` — one line per probe: task, candidate, checks, duration, model.
- `...harness/improvement.md` — current adoption table, regenerated by the runner.
- Memory MCP — `Orchestrator_reflect` and `Orchestrator_episode` carry lessons
  across sessions; `Orchestrator_memory(action:"procedure")` stores reusable steps.

A lesson enters the harness only after a probe contrast supports it. No contrast,
no adoption.

## Change Discipline

- One component per change. Mixed edits cannot be attributed.
- Keep the baseline runnable. A rejected candidate must leave no trace except
  its ledger line.
- Re-run `make check` after every harness edit; the gates are cheap.
